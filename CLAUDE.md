# Alloy — Coding Standards & Conventions

## Project Structure

```
packages/engine/   — @alloy/engine: Pure game logic, zero UI deps, dual CJS+ESM via tsup
packages/client/   — React 19 + Vite SPA, the game UI
packages/pixel-forge/ — Node CLI pixel art pipeline (code-drawn + Gemini sprites → sprite sheets)
```

Engine is the single source of truth for all game rules. No game logic in the client.

## Tech Stack

- TypeScript 5.7+, strict mode, ES2022 target
- pnpm 9+ workspaces
- React 19 + React Router 7 + Zustand 5 + TailwindCSS v4 + PixiJS 8
- Vitest 3.x for unit tests, Playwright for E2E
- Zod 3 for data validation

## Versioning

The client surfaces its version as "Alloy v{version}": in the title screen's corner (`src/pages/TitleScreen.tsx`) and in the Delve's Settings (`features/delve/hub/SettingsPanel.tsx`). Source of truth is `packages/client/package.json#version`, which both import directly.

**Bump the version whenever you ship user-visible changes** (UI tweaks, balance tweaks, new features, bug fixes that affect play). Follow semver: patch for fixes, minor for features, major for breaking. A one-liner in the relevant commit: `chore(client): bump version to 0.X.Y`.

## Testing

- **Engine tests**: `packages/engine/tests/*.test.ts` — Vitest, Node environment. A file whose tests run synchronously past 60 s in all yields after each test (`afterEach(() => new Promise((r) => setTimeout(r)))`), else vitest's pending task update times out ("Timeout calling onTaskUpdate", unhandled errors though every test passes)
- **Client unit tests**: `packages/client/src/**/*.test.{ts,tsx}` — Vitest, jsdom. Store tests live in `src/stores/` (NOT `__tests__/` subdirectory)
- **E2E tests**: `packages/client/e2e/*.spec.ts` — Playwright (`playwright.config.ts`), three Chromium projects: `desktop` (1280×800, every spec but the responsive ones), `desktop-1080` (the `delve*.spec.ts` again at 1920×1080, the Delve's design size) and `responsive` (`e2e/responsive/`: layout probes over a viewport matrix, every Delve screen again at Text size Large on 1920×1080 and Medium on 1280×800, `TEXT_VIEWPORTS`; text under 12 CSS px fails)

### TDD Pattern

For new features, follow this cycle:
1. Write the failing test
2. Run it to verify it fails
3. Implement minimal code to make it pass
4. Run to verify it passes
5. Commit

### Determinism

All game systems must be deterministic given the same seed. Use `SeededRNG` from `packages/engine/src/rng/seeded-rng.ts`. Fork RNG streams for independent subsystems (e.g., `rng.fork('layout')`).

## Code Patterns

### Engine

- Types go in `src/types/` — one file per concept (`gear.ts`, `rune.ts`, `quests.ts`, etc.; `Rarity`, `RARITY_ORDER` and `rarityIndex` live in `gear.ts`)
- Game logic modules: `src/arpg/` (the real-time sim), `src/delve/` (the hero, the dive, the profile ops), `src/loot/` (items, drops, crafting), `src/rng/` (`SeededRNG`), `src/data/` (the data files and the registry)
- Data files: `src/data/*.json`, loaded and validated via Zod schemas in `src/data/schemas.ts`
- `DataRegistry` in `src/data/registry.ts` is the single access point for all game data; it takes one object, `{ balance, delve, arpg, crafting, quests }` (`LoadedData`, from `loadAndValidateData()`; `createDefaultRegistry()` builds it)
- All balance-tunable values go in `balance.json`, accessed via `registry.getDelveBalance()`

### Client

- Pages in `src/pages/` — the title screen (`TitleScreen.tsx`, `/`) and the Delve's screens (`DelveCamp`, `DelveRun`, `DelveTraining`, `DelveLab`)
- Stores in `src/stores/` — Zustand, minimal state (visual/UI only, no game logic)
- Animations: Web Animations API on actual DOM elements, never spawn duplicates

### Naming

- Files: kebab-case (`hero-stats.ts`, `seeded-rng.ts`)
- Types/interfaces: PascalCase (`GearItem`, `HeroStats`)
- Functions: camelCase (`computeHeroStats`, `settleDive`)
- Constants: UPPER_SNAKE_CASE (`MAX_SOCKETS`, `RARITY_ORDER`)

## The Delve — the game

Real-time top-down ARPG behind the title screen's Delve button. Loop: fight packs through a floor's rooms and halls to its exit (see Floor maps), materials and currency burst onto the floor and fly to the hero (gear drops only from elites and bosses), push deeper or extract (one power-up at each stop between depths; a death loses the floor's haul and a share of what the dive banked), then forge gear from those materials at the Anvil, repeat (see Crafting); a new save may take Hesta's guided start first (see Guided start). The hero has four skills, each a **chain** of up to five **moves** carried by the weapon (see Weapon movesets) that the player builds at the Anvil: an automatic **basic** attack from the weapon, whose blows each take a kind and an element of the hero's pair, and a **Primary**, **Defensive** and **Ultimate** (Q/E/R), whose moves each take a **kind** (light, medium, heavy, or a **hold** that charges while its button is held and fires on release, reaching full power at full charge), a **form** (12, e.g. Bolt, Ward, Maelstrom) and one or two of six **elements** (fire/frost/storm/earth/shadow/nature; two make a fusion such as Wildfire), with one **payment** per chain (mana, charge or a cast wind-up). Each press casts the chain's next move, each landing harder than the last (the step bonus), and each move has its own cooldown. After a move lands its slot waits a **beat** before the chain's next move (by the kind it played as, its slot and the weapon's **tempo**); a press meanwhile waits in its slot's buffer and fires at the beat's end, while the other slots, the dodge and the basic attack stay free. A pause, counted from the beat's end and stopped while the slot's button is held, starts the chain over (spec: `docs/superpowers/specs/2026-09-29-delve-chain-feel-design.md`). One mana pool: basic hits fill it, abilities spend it. Gear carries a mana element: attunement grows the pool, powers abilities of that element and grants masteries at 10. Mixing elements triggers reactions: every pair of elements has one, set off both ways (15, from Melt to Galvanize). Basic attacks are manual by default, or automatic (a device preference, "Basic attack" in the Controls editor: hold left click to attack toward the cursor, RB on the pad, or click the HUD's Attack slot for one blow; `ArpgInput.attack`/`attackAim`; a hold blow charges at its strike point while the attack is held and re-aims as it strikes). Each weapon has a feel row per kind (`delve.json` `feel`) and a default basic chain (`defaultChain`) that plays its old combo string blow for blow. Every attack and ability runs startup → strike → recovery: a move's kind sets its conjure, forward forms step in and Bolt, Volley and Lance recoil, and Burst is thrown (spec: `docs/superpowers/specs/2026-09-25-delve-combat-weight-design.md`). Nothing roots the hero: while a swing, a charging hold blow, a wind-up or a charging hold runs it walks at `actionMove` (0.6×), facing the action, and every blow's and form's motion adds on top of the steering, less any part against it. Each weapon moves its own way, its rows' `move`, `side` and `hop` growing with the kind: the dagger darts in and hops out, the sword steps in and lunges, the axe wades, the maul plants then leaps (a charged hold blow leaps as it is let go, then strikes; a leap under `feel.minLeap`, such as unarmed's, or when its foe is already that close, is skipped and the blow strikes on release), the staff sways side to side, the wand circles its target and the bow steps back (spec: `docs/superpowers/specs/2026-09-29-delve-weapon-flow-design.md`). A **dodge** (Space, B or the HUD's Dodge slot; 2 charges that refill) dashes with i-frames; an attack that would have hit early in it (even where it began) is a **perfect dodge**: the charge comes back, the next real hit crits and staggers, and the display slows for a beat (spec: `docs/superpowers/specs/2026-09-26-delve-dodge-design.md`).

- **Elemental affinity** (spec: `docs/superpowers/specs/2026-09-27-delve-elemental-affinity-design.md`): each hero has a pair, `profile.pair` (`{ primary, secondary }`; "affinity" already means an item's mana). A new save chooses its primary on the Anvil (`features/delve/ManaChoice.tsx` → `chooseStartingMana`: the equipped gear re-attunes to it and the weapon's moveset resets to its base slots in that mana); a second element is bound between dives, for free (`bindSecondary(registry, profile, mana)`: from the Mana view in the Skills tab, `ManaPanel.tsx`, or the bind choice the Loadout's compare pane shows when equipping off-pair gear, `hub/loadout/BindChoice.tsx`), and after that only `realign` (Mana Dust + scrap) or an overtake changes the pair. Every op lives in the engine's `src/delve/pair.ts` and refuses while `isDiveActive` (but the choice). Attunement counts only for the pair: take a hero's real stats from `profileStats(registry, profile)` (`computeHeroStats` with `{ pair, filterAttunement: true, basic }`: its basic chain too), never plain `computeHeroStats`, and value a candidate with `compareItem` (a weapon as a home for your moveset, or `'asIs'`). Each basic blow strikes with its own element (a weapon's default blows are all in its mana, the starting weapon's in the primary; the Training Grounds' default puts its last blow in the secondary; `HeroBlow.attunePower` grows with that element's attunement, none off-pair), and nothing re-colours a weapon's moves on its own: equipping, a bind, an overtake and a re-attune leave them as they are (only the Training Grounds keep `followBasic`/`isDefaultBasic`, in `arpg/abilities/resolve.ts`, for their default basic chain). In the Delve, a new move uses only the pair (`setChains`; `fixChainsToPair`: a realign maps every move's and blow's element of the equipped weapon by its old role, `roleHeir`), while the Training Grounds stay unrestricted with their own `primary` and a `secondary` for the blows. A secondary above `overtakeMargin` × the primary's attunement swaps in when a dive closes (`resolveOvertake`, from the store's `closeDive` and the autopilot's `betweenDives`; the Mana view shows `overtakeProgress`, the same rule). Drops lean toward the pair (`rollMana`); salvaging off-pair gear gives Mana Dust (`salvageDust`; it is a floor drop too), spent on Re-attune (`reattuneItem`, priced by `reattuneCost`, on the Forge's Temper bench) and Realign. Numbers: `balance.json → delve.pair`. The store's `notices` queue becomes toasts on the Delve pages (`useDelveNotices`).
- **Elemental stacks and pair reactions** (specs: `docs/superpowers/specs/2026-09-28-delve-elemental-stacks-design.md`, over `docs/superpowers/specs/2026-09-28-delve-pair-reactions-design.md`): every hit applies **stacks** of each element status it carries (`StatusState.stacks`, 0 to `stacks.cap` per element, and one timer per element, `stackUntil`, that any new stack of it refreshes; at the timer they all lapse together, at the top of each step (`lapseStacks` in `arpg/step.ts`, before the hero, projectile, zone and monster ticks)). A blow applies its kind's `basicByKind` (light and medium 1, heavy and hold 2), an ability's direct hit its kind's weight's `byWeight` (`ResolvedAbility.stacks`), anything else `tick`; the count rides `HitOpts.stacks` (`Projectile.stacks` for shots), and `applyStatus(…, n)` maps a status to its element through `BASIC_STATUS`'s inverse (`applyStacks` in `arpg/combat.ts`). The count is the status and its strength, along a diminishing curve (`stacks.curve`, cumulative, 1 to 3.5 over five stacks; past its end each stack adds its last step; `stackIntensity`): a burn deals `burnRef × firePerStack × curve` a second and poison `poisonRef × poisonPerStack × curve`, shock and hex add `perStack × curve` damage taken, frost slows linearly per stack (capped) and freezes on *crossing* `freezeAt` (checked once per hit, `crossFreeze`), and Earth's stacks (the rattle) come only from a stagger by a source that includes Earth (`HitOpts.rattles`); `isBurning` and the rest read `stacks[el] > 0`, and `hasMark` also counts a bare freeze as frost. Every pair of elements reacts, both ways: a hit pairs its element's stacks off against the first other element, in `MANA_TYPES` order, with stacks from earlier hits (a bare freeze is one frost stack to a partner; `findPair`). A damage reaction (Melt, Shatter, Overload, Combust, Crystallize: `DAMAGE_REACTIONS`) takes every pair, the smaller count, and adds its bonus once per pair (Overload's blast grows per pair; `react(…, n)`); the other ten fire once and take one pair, so the rest of both statuses stay. `consumePairs` takes the pairs off both sides (a freeze ends when frost was the partner, except under Superconduct), and no reaction fires on that foe for `reactionLockout` (`StatusState.reactionLockUntil`); a killing reaction consumes nothing. The table is `arpg.json → reactions` (`elements`, `cooldown`; `registry.getReactionFor(a, b)`), checked by one `ReactionIdSchema` that the save's `reactionsSeen` uses too, and each effect is one `case` in `react`. The eight added in v0.44.0: Obsidian (a barrier, `HeroEntity.barrier`, soaking in `shieldHero` after the Defensive and before the Ward), Lightning Rod (`refundDodgeCharge`, `quickUntil`), Sunder (`sunderUntil`), Seedling and Siphon (an orb and motes, which the Training Grounds get too), Crystallize, Blackout and Galvanize; the five buff ones wait `reactionCooldown` (`HeroEntity.reactionReadyAt`). Numbers: `balance.json → delve.stacks` and `delve.reactions`. The client draws the stack pips under each foe and the lasting states in `fx/draw-world.ts`, the moment in `arena/fx/reactions.ts` ("MELT! ×2" from the `hit` event's `pairs`), and the barrier and Galvanize on the HUD through the snapshot; the Training meter counts pairs. `tests/delve-pacing-pairs.test.ts` sweeps all 15 pairs, forced (`AutopilotOptions.secondary`), each pair's mean depth at dive 4 over eight seeds within 0.6–1.6 × the median.
- **Weapon movesets** (spec: `docs/superpowers/specs/2026-09-30-delve-weapon-movesets-design.md`): the chains live on the weapon, `GearItem.moveset` (`{ chains, slots }`). Its rarity decides which skills it carries (`balance.json → delve.movesets.carries`, since v0.62.0: common the Basic alone, uncommon and magic add the Primary, rare the Defensive, epic and legendary all four; unarmed the Basic alone; an awakened rare (`GearItem.awakened`: see Crafting's Awaken) the Ultimate too; `carriedSkills(registry, item)`, which reads the item's rarity and `awakened` (null: unarmed) and is threaded through `MovesetOwner`, `defaultMoveset`, `movesetTransfer`, `forgedMoveset` and `fitMovesets`, so an awakened Ultimate survives load and transfer; `carriedFrom`, the least rarity that carries a skill; and `carriedByText`, "Carried by rare weapons and better" (the Ultimate's adds ", or an awakened rare"), which `MovesetView`, the chain builder's locked skill and Help show); a new save's common sword carries the Basic alone, so a Jump in hero's Primary comes with its first forge (the kit's uncommon flux), and the autopilot forges one before dive 1; a skill it doesn't carry has no chain, a null entry in `HeroEntity.chains` that every reader passes over (its key, HUD button and pad button do nothing, and the HUD hides the button). Each chain holds 1 to its slots' moves; a chain starts at its base slots (the Primary, Defensive and Ultimate 1, the basic chain its weapon's `defaultChain` length; `baseSlots`) and grows to 5. The pure parts live in `src/loot/moveset.ts`: `heroChains(registry, equipped, pair)` (the equipped weapon's chains, or unarmed a default moveset in the pair's primary, the Basic alone, never stored), `movesetOf`, `defaultMoveset`, `extraSlots`, and a drop's `rollMoveset` (extra slots by rarity, `delve.movesets.extraSlots`, spread at random, from `rng.fork('moveset')` after every other roll, so every other stat is as before); the profile ops live in `src/delve/moveset.ts`. **Links** (`profile.links`) come from salvaging a weapon (one per extra slot or open socket past what a forge of its rarity grants, `crafting.weaponExtras`) and as floor drops; `addSlot` buys a slot at the chain's end for Links and scrap by its position (`slotPrice`: `slotLinks`, `slotScrap`), its move the next default kind, the last move's form, and its elements while in the pair. Edits cost Mana Dust (`movesetEditPrice`, priced by origin since v0.51.0, the builder's record of where each new move came from (`ChainOrigins`: `origins[skill][j]` the saved index move `j` came from, null for a new move; missing origins are the identity map): the moves whose origins form the longest increasing run are in place and free, any other moved move costs `editDust`, a kept move's changed kind or form `editDust` and its changed elements `elementDust`, a new move and a removed one `editDust` each (so removing a move and adding one alike costs 2 × `editDust`: 4a's matching moves by what they are is retired), `elementDust` once per Apply for each new element set, and a changed payment `editDust`; an Apply is never dearer than its edits one by one, and equal when no move is removed; `editPrice` applies the first-dive freebie), through `setChains` (all or nothing, a `ProfileActionResult`; `setChain` is its one-chain case), which refuses mid-dive, unarmed, past the slots, unpaid, and an element set outside the pair held more times than before (a drop's off-pair move is kept, casts and reacts, but draws no attunement). `transferMoveset` moves the equipped weapon's moveset onto a bag weapon (`movesetTransfer`: each chain's extra slots move, `transferScrap` each; - **Runes** (spec: `docs/superpowers/specs/2026-09-30-delve-runes-design.md`): every move and basic blow holds **sockets**, `Move.runes` / `Blow.runes` (`(RuneRef | null)[]`: its length the open sockets, `null` an empty one, absent none; `RuneRef` is `{ id, tier }`, tier 1–5 shown I–V), each holding one **rune**. A move starts at 0; the cap per move is the weapon rarity's (`socketCap`: common and uncommon 1, magic and rare 2, epic and legendary 3, at most `MAX_SOCKETS`; unarmed 0), a socket is opened for Links and scrap by its index (`socketPrice`: 1 + 20, 2 + 40, 3 + 60) and never closed, and weapon drops roll some open by rarity (`rollSockets`, from `rng.fork('sockets')` after the moveset, so every other stat rolls as before). Loose runes live in the pouch, `profile.runes` (`RunePouch`: rune id → five counts by tier; no bag space). The 14 runes are data rows in `src/data/runes.json` (`RuneDefSchema`; `registry.getRunes` / `getRune` / `findRune`) in four families: Shape (Split, Multi-shot, Pierce, Chain, Widen), Tempo (Quick, Echo, Heavy), Elemental (Saturate, Linger, Volatile) and Sustain (Leech, Drain, Guard). A row holds five tiers of **knobs**, its fits (`fits.forms`; `fits.weapons`, whose basic blows it fits; `fits.kinds`, the blow kinds it acts on, dormant on any other) and its text templates, which only `runeText` fills (the client never formats a rune's numbers); the pure helpers live in `src/loot/runes.ts` (`runeFits`, `runeActive`, `runeKnobs`, the pouch's). The sim reads only knobs: `resolveAbility` and `computeHeroStats` merge a move's active runes with its elements, fusion and legendaries (`mergeKnobs`, `NEUTRAL`; `ResolvedAbility.runes` and `HeroBlow.runes` are the runes acting, the list the builder's dormant marks and the HUD both read), and each new knob has one handler: `split` (`impact.ts`, and a basic shot's hit in `step.ts`: evenly spaced shards, `form: 'shard'`, that never split, chain, linger, echo or burst), `extraShots` (`resolve.ts` adds to Volley's and Barrage's count, with half the per-shot cut on Volley and none on Barrage, `extraShotPower`; `forms.ts` fans Bolt and Lance, `basic.ts` a shot blow), `echo` (`abilities/echo.ts`: `queueEcho` / `echoTick` replay the move as it landed, or a blow through `landBlow`, `echoDelay` later, free and never echoing again), `quick` (cooldown and wind-up, and the beat through `moveBeat`; a blow's cycle and startup), `stacksBonus` (Saturate), `catalyst` (Volatile: adds to the Catalyst legendary's factor in `react`), `manaOnHit` (Drain: mana per foe-hit, up to `drainFoes` foe-hits and `drainShare` (half) of the move's own mana cost before its runes' load (`baseCost`) a cast, a blow at most half a blow's mana, counted per skill in `HeroEntity.drained` and `drainLeft`; a move paid with charge gets none) and `guardOnLand` (Guard: `guardLand` in `defend.ts` feeds Obsidian's barrier and never extends a larger one); the hit-time knobs ride `HitOpts` through `knobHitOpts`, and `Knobs.pierce` is a count (`true` in data is `Infinity`; a shot's `Projectile.pierceLeft` counts down, `pierce` stays its spawn flag). **Shape runes add, they don't multiply:** past its first foe, a shot that a finite Pierce carries on still hits each foe it passes, but its Chain jumps, Linger zone and Split shards come off its first foe only (`ImpactOpts.through`); an Earth shot's endless pierce keeps its impact at every foe. **Linger** leaves at most one zone a shot and `ZoneKnob.perCast` (3) a cast, counted per skill (`HeroEntity.zonesLeft`, spent by `spendZone` in `leaveZone` and `blowZone`), an Echo's out of its cast's three; an element's or a fusion's zone has no `perCast` and is uncapped unless merged with Linger (`mergeKnobs` takes the smaller `perCast`). A new rune from existing knobs is one row in `runes.json`; one that needs a new knob adds it to `Knobs`, `NEUTRAL`, `mergeKnobs` and `KnobsSchema`, its one handler, and its term in Power's `damagePerUse` or `estimateCombat`. **Changing runes** goes through the Anvil's draft with every move edit: `setChains(registry, profile, chains, { origins, unsocket })` (`delve/moveset.ts`) charges the per-origin Dust (see Weapon movesets) plus `runeChange` (`src/delve/runes.ts`: socketing is free, out of the pouch; opening a socket costs its Links and scrap; a rune that ends up elsewhere is a pull plus a socket; a removed move's sockets come back as Links and its runes are pulled; Links are netted, so the Links an Apply leaves don't depend on the order of its edits), and refuses a rune that doesn't fit its move (so a form change while one wouldn't fit), the same rune twice on a move, past the cap, fewer sockets on a kept move, and an unpaid draft or pouch; `draftPrice` is the builder's total (`openSocket`, `socketRune` and `fuseRunes` are single ops). **The pull rule**, `unsocketMode` (`delve.runes.unsocket`): `'destroy'` as shipped, or `'pay'` (`pullScrap` by tier, the rune back to the pouch); dev builds override it with the system menu's "Pull: destroys / pays" chip beside "Restart Delve (dev)" (localStorage `alloy:delve:unsocket`), though the load-time trims always use the balance's mode, never the override. **The parts rule:** a socket that goes other than through Apply (a salvaged weapon, a transfer's dropped or capped moves or unfitting blow runes, `chooseStartingMana`, the load-time trims; `settleParts`) comes back as one Link, its rune destroyed or back to the pouch free by the pull rule; the results carry `runes` and `destroyed` for the toasts. A transfer moves each kept move's sockets with it (`transferScrap` each). **Drops:** `dropRune` (`arpg/rune-drops.ts`, called in `killMonster`, never in the sandbox) rolls on `world.runeRng` (`dropChance` by foe kind, × the door's `runes`; a boss always drops one; the tier by depth, `tierDepths`, and `tierUp` for one higher); a rune drop is walked over like an item, no magnet, and rides the floor's haul into the pouch (`BankResult.runes`, `DiveState.runesEarned`; see Crafting's banking). **Fusing:** `fuseRunes` turns `fuseCount` (3) of a rune and tier into one of the next tier for `fuseScrap`; tier V doesn't fuse. Runes are gear: locked mid-dive, but for the stop's fifth kind, `'rune'`, which sockets one pouch rune into an open empty socket. Power values socketed runes through `damagePerUse` and `estimateCombat` (Drain's terms under the same cap), net of their price (see Rune costs). **The autopilot** (`delve/autopilot.ts`, between dives) spends Links on slots up to three a chain (`SOCKETS_AFTER`), then on sockets, each opened only where a pouch rune that fits it raises Power and filled at once (`bestRune`: the cheapest first, the Primary's moves first, then Basic, Ultimate and Defensive), then on the 4th and 5th slots; it sockets each socket with the pouch rune that raises `profilePower` most and fuses only the copies left over. At load `fitMovesets` empties unknown and repeated runes and trims sockets past the cap (each socket back as a Link). Numbers: `balance.json → delve.runes`. The client: the presentational pieces live in `features/delve/runes/` (`SocketRow`, `RunePicker`, `RuneGlyph`, `ItemSockets`, and `rune-style.ts`'s family colours: Shape cyan, Tempo amber, Elemental violet, Sustain green); the Skills tab's move cards show their sockets (a click opens the move's editor at one), and the move editor lists each socket as a row that opens the rune picker as a grid (`RunePicker`'s `grid`), offering the pouch runes that fit, each with what it does to the chain's damage a second (`damage`), and the Apply sheet shows the draft's price and what it destroys; the Forge tab's Materials bench holds the pouch and Fuse (`RunePane`); a weapon's moveset (`MovesetView`, in the compare pane) lists its sockets and runes, and a transfer's price its sockets; the stop has a rune pick; the arena flashes `runeFx` (`arena/fx/runes.ts`: split, echo, volatile), draws rune drops in their family's colour with a plaque ("Split III"), and dots each HUD skill slot (and the Attack slot) with the next move's runes (`RuneDots`; `AbilityHud.runes`, the snapshot's `basicRunes`; each dot's `data-rune` its id); the Training Grounds socket any rune at any tier, free, up to 3 a move. **The balance gate** (the DPS Lab's `'rune'` view and `runeComboSetups`, every three-rune set of a form or a weapon's blows, at tier III, measured with the loads zeroed since v0.52.0): no single rune above 2.0× its `none` row on one dummy or 2.5× on the pack, and no three-rune set above 3.0× on one dummy or 4.0× on the pack. Five sets stay above 3.0× on one dummy, all a Nova with Linger (up to 5.97×), accepted as a yardstick artefact: a Nova lands twice in 30 s, so its one-dummy baseline is two blasts; the whole fight gains about 30%, and on the pack those sets read 3.2–3.4×, under 4.0×. **Rune costs** (spec: `docs/superpowers/specs/2026-10-01-delve-rune-costs-design.md`; v0.52.0, no save change): every rune row has a `load`, five fractions by tier that never fall (`RuneDefSchema`), its price. A move's raw load is the sum, over the runes acting on it (`ResolvedAbility.runes`, so a dormant rune costs nothing), of `runeLoad(registry, ref, form)`: the tier's load × `bySlot[slot]` × `byForm[form]` (1 when missing). Attunement in the move's elements (their mean, as `attunePower`) eases the sum once: `load = raw × (1 − ease)`, `ease = min(easeCap, easePerAttune × attunement)` (`loadEase`), both on `ResolvedAbility` (`load` and `ease`, the ease set with or without runes). `resolveAbility` raises the price in the chain's own payment: a mana move's cost and a cast's mana × (1 + load) (one product with Manaweaver and `castManaMult`), a charge move's `chargeNeed` × (1 + load × `charge`) (`chargeCap` follows), and a cast's channel × (1 + load × `cast`), the conjure untouched. No cooldown changes, the charge lockout included; basic blows are free, and an Echo stays free. Every sim reader follows unchanged (`canAfford`, `pressDue`, `startHold`, `releaseHold`, `pay`, the HUD), and Drain's cap is on `baseCost(ab)`, the cost before the load. The factors live in `balance.json → delve.runes.load` (`bySlot`; `byForm`, whose keys are checked against the forms; `charge`; `cast`; `easePerAttune`; `easeCap`, at most 1). `loadText` and `runeText`'s price terms (`{ payment, ease }`, its `cost`) are the only formatters: "+N% cost", "+N% charge", "+N% cast wind-up, +N% cost". A blow and a dimmed rune show no price; the picker shows the move's eased price and the pouch the raw one. The builder's pay line appends "(runes: …)", a line says "Attunement eases rune cost by N%" ("(the most it can)" at the cap), and a mana or cast chain shows "Spends X/s · your build refills Y/s" (amber when over) from `manaSupport(registry, stats, chain)`: the spend at the chain's cadence, and `basicIncome` (regen, the basics and their Drain) plus the chain's own Drain. Power nets the price through `useInterval` and the pool through `valuedChain`, so the autopilot sockets a rune only where it raises Power. **The two-build gate** (`tests/delve-rune-costs-gate.test.ts`, skipped unless `RUNE_COST_GATE` is set): for each Primary form, its best three-rune tier-III set (ranked with the loads zeroed) against the rune-less chain, sustained on the pack (`DpsOptions.sustained`). Starved is reported (target about 0.9–1.2×), supported must reach at least 1.5×, and the mana per press must be 2.0–3.0× on the starved hero. Measured at v0.52.0: supported 1.62–2.07× (lowest Lance), starved 1.01–1.18× (Volley 1.34×), the mana per press 2.89× starved and 2.07× supported. When it fails, tune `byForm`, then `bySlot`, then `easePerAttune` / `easeCap`, then the rune rows; never the ceilings, the floor, the band or the pacing rails.
- **Crafting** (spec: `docs/superpowers/specs/2026-10-02-delve-component-crafting-design.md`; v0.58.0, save v8): gear is rare and forged; the main loot is materials. They live in the **materials pouch**, `profile.materials` (`MaterialsPouch`, beside the rune pouch, no bag space; types in `src/types/crafting.ts`, pouch ops in `src/loot/materials.ts`): **metal bars** (7, Rusty to Voidforged, `crafting.json → metals`, each an item-level band, the bands partitioning item levels from 1 (a schema check); `metalAt`, and `materialName` names an item by its level's metal), **flux** (uncommon, magic, rare, epic: bar + flux is an ingot of that rarity, none common), **affix shards** (one per affix stat, tiers I–V, each tier a roll band, `shardTiers`; `affixShardTiers` overrides an affix's, the `*Attune` shards having two; `shardTiersOf`) and **essences** (one per legendary, keyed by its id); **patterns** (one per base) are learned, not held (`profile.patterns`), and scrap, Mana Dust and Links are floor drops too. A new save starts with `crafting.json`'s kit: the sword's, the cuirass's and the dagger's patterns, 5 Rusty bars, 5 uncommon flux and 50 scrap (`startingPatterns`, `startingMaterials`). **Forging** (`forge(registry, profile, req)` in `src/delve/crafting.ts`, the rolls in `src/loot/forge.ts`; `ForgeRequest { baseId, metal, flux?, essence?, element, shards }`): a learned pattern; the bar sets the item level, `clamp(bestDepth, band)`; the flux the rarity, epic flux + an essence a legendary whose `slots` hold the base's; either element of the pair is free, another costs `offPairDust`; up to `loot.affixCount[rarity]` distinct shards each set a line in its tier's band, and the lines left roll at random, never another element's `*Power` or `*Attune` (`foreignElementStats`, Reforge too); a forged weapon carries its rarity's skills and `crafting.weaponExtras` (extra slots to the Primary first, then Basic, Ultimate, Defensive; sockets one a move, the Primary's first: `forgedMoveset`). Its price is `forgeScrap[rarity] × scrapLevelFactor(ilvl)` plus what it consumes; it refuses mid-dive, an unknown pattern, missing materials or scrap, a shard its slot doesn't allow or a repeated one, too many shards, an essence that doesn't fit, and a full bag, each with a reason (`ForgeRefusal.code`). `previewForge` is everything `forgeItem` makes but the draws (each line's band, the floor, the implicits, the price, the refusal, a weapon's skills, slots and sockets) and the bench renders only it; `forgePowerRange(registry, profile, req)` (`delve/crafting.ts`) is the forge preview's Power against what is worn: the item at the bottom and the top of its bands (the floor applied; random lines left out, `random` counting them), valued by `compareItem` (a weapon as a home). Every forge, hone, reforge and imprint draws on `forge:${forgeCount}` (`forgeRng`) and bumps it; a forged item goes through `recordFinds`. **The roll formula:** a line's `roll` stays its place in the affix's whole range; it rolls in its band (`StatRoll.band`, a shard's, else `[minRoll[rarity], 1]`) lifted by the **attunement floor** (`rollFloor`: `min(attuneRoll.cap, attuneRoll.perPoint × A)`, `A` the hero's attunement in the item's element, 0 off the pair): `u = floor + (1 − floor) × r`, `roll = bmin + (bmax − bmin) × u` (`rollBand`), the legendary power's roll too, implicits not. **The Temper bench** (between dives): Upgrade and Re-attune as before, **Reforge** (a random other affix, its `band` cleared, the floor applied), **Hone** (`hone`: the line's value again within its band, for `honeScrap × rarityCostMult × honeGrowth ^ hones × scrapLevelFactor`; `GearItem.hones` +1) and **Imprint** (`imprint`: a chosen shard's affix over a line, in the shard's band, for the shard and `imprintScrap[rarity]`; `imprintRefusal` says why not) and **Awaken** (`awaken(registry, profile, uid)`, v0.62.0: a rare weapon carries the Ultimate too, `GearItem.awakened`, its moveset gaining the Ultimate's base chain in the pair's primary; once, for `awakenPrice`: `crafting.awaken`'s epic flux, Links and scrap × `scrapLevelFactor`; refused mid-dive, on anything but a rare weapon, on an awakened one and unpaid; Upgrade, Reforge and a Transfer keep the flag with the weapon). Alloy Fusion is gone. **Refining** (`refine`, `refineCost`, `refinedRef`): 3 bars, flux or shards of one kind and tier make one of the next for scrap (`refine.metal`, `refine.flux`, `refine.shard.scrap[tier]`); Voidforged, epic flux, a shard's last tier and essences don't refine. **The shard bench** (`buyShard`) sells a tier I shard of any affix for `shardBench { scrap, dust }`. **Salvage** goes through `applySalvage` on every path (the Loadout's Salvage and Salvage junk, auto-salvage and a full bag in `addLootToBag`; `salvageYield` is the Loadout's preview), on a stream keyed on the item (`salvageRng`: the dive seed's fork mid-dive, the profile's with `forgeCount` at the Anvil): scrap, one shard of a random line at the tier `salvageShardTier` gives its roll (never past its affix's tiers) and at `salvageExtraShard` a second, the base's pattern if unknown, a legendary's essence instead of a shard, a weapon's Links (`salvageLinks`), its runes by the parts rule and an off-pair item's Mana Dust; mid-dive all of it rides the floor's haul. **Drops** (`balance.json → delve.drops`; `rollMaterialDrops`, pure, and `dropMaterials`, on `world.materialRng` inside `killMonster`'s sandbox guard, so gear, rune, orb and mote rolls are untouched): each kind's table holds entries `{ chance, count }` (× the door's `materials`, at most 1): normal foes drop bars, Mana Dust, shards and rarely Links, never gear; - **Quests** (spec: `docs/superpowers/specs/2026-10-03-delve-quests-design.md`; v0.59.0, save v9): goals and rewards, never a lock, all given by **Hesta, the Anvil-keeper** (`quests.json → giver`; her `hesta` sprite is code-drawn in `packages/pixel-forge`, `art/alloy/sprites/hesta.ts`, 26 px for a size of 1.6, idle and a hammer lift): a main chapter ("Embers of the Anvil", six quests, each unlocking when the one before is complete, claimed or not (since v0.62.0, so progress flows through a dive); `clearFloor`: `biome`, `noPotion`, `noDamage`, `minDepth`, `minRoomsCleared`; `extract`: `minDepth`; `boss`: `biome`; `reaction`: `reaction`, or `pair`, the pair's own as it is when the event applies; `perfectDodge`; `forge`: `minRarity`, `legendary`; `refine`; `openSocket`), a **max** (`reachDepth`, a `total` one reading `bestDepth` too) or a **state** read from the profile (`bind`, `knowPatterns`, `discoverReaction`); progress caps at the count, and a done objective stays done. `scope` is `total` (from the unlock) or `dive` (back to 0 at a dive's start and settle, `resetDiveQuests`; the schema refuses it on the Anvil-only types, `anvilOnly`). `unlock` is `{ after?, bestDepth?, reactionsSeen?, patterns?, pair? }`, all required (none: unlocked on a new save). **Quest events** (`QuestEvent`): the arena pushes them onto `WorldPending.questEvents`, always under `!world.sandbox` (`kill` in `killMonster`, `reaction` in `noteReaction`, each one, `perfectDodge` in `dodge.ts`), and keeps the floor's flags `ArpgWorld.potionDrunk` and `hurt`; `bankWorld` applies them; `completeFloor` emits `clearFloor` (with `roomsCleared` on a generated floor) and, on a boss floor, `boss` (a boss counts only there, never as a kill, so a replayed floor can't double it); `startDive` and `chooseDoor` emit `reachDepth`, `extractDive` `extract`, and at the Anvil `forge`, `refine`, `bindSecondary` (`bind`) and `setChains` (one `openSocket` per socket its Apply opens; `openSocket` goes through it). **One function**, `applyQuestEvents(registry, profile, events)`, pure: it advances every unlocked, unclaimed quest's and every contract's matching objectives, reads the state types again, then runs the unlocks, walking the quests in chain order until nothing new unlocks, so one call can cascade (`unlock.after` is met once that quest is complete; a quest newly unlocked reads its state at once, so an early bind completes A Second Flame, but doesn't count that call's events; a new main quest takes the tracked slot of the one it follows even while that one waits to be claimed, or the first free one); every emitting op calls it and returns its profile (no result type changed), and an op that only changes a state (salvage's patterns, a bank's `reactionsSeen`, a claim's pattern) calls it with no events. **Progress always counts**, death or not: only rewards wait. **Claims** (`claimQuest`; refused while `isDiveActive`, the Anvil mid-dive included, as `rerollContract` is: "Finish or leave the dive first", `DIVE_OPEN`): the rewards (`Reward`: scrap, dust, links, metal, flux, shard, essence, pattern) go straight to the stockpile through `resolveReward` (`src/delve/rewards.ts`), on `quest:<id>:<claimCount>` from the profile seed (`grantRewards`), which settles the rules: `metal: 'depth'` the best depth's metal, a shard rule a random affix of its family at its tier, `essence: 'fit'` a legendary that fits a learned pattern, `pattern: 'unknown'` an unknown pattern, else its `fallback`. A claimed quest leaves `tracked` and moves to Done; `trackQuest` (up to `maxTracked`) and `markQuestSeen` work mid-dive. **The Contract board** (`src/delve/contracts.ts`): `profile.quests.board`, `contracts.slots` (3) slots, each a contract or empty; `generateContract` makes one from `quests.json → contractTemplates` on `contract:<boardCount>` from the profile seed (reloading never rerolls; its id `contract:<n>`), naming only what the hero can do (`possible`: the biomes reached and their mana, the pair's reaction and `reactionsSeen`, depth goals within `[max(2, bestDepth + depthWindow[0]), bestDepth + depthWindow[1]]`, a boss only within that reach, forge goals up to the best flux grade owned, `noPotion` floors from `bestDepth − flagDepthBelow`) and passing over a template already on the board while another fits; a tier drawn by `tierWeights` sets the count from its range (a kill or reaction goal × (1 + `countScale` × bestDepth), so a new save's take one or two dives) and the rewards × (1 + `depthScale` × bestDepth), and a hard one may add an essence (`essenceChance`, × Lucky Charm's boost, rolled at generation; never while `bestDepth` is below `essenceMinDepth`); the Untouchable side quest gives epic flux where it gave an essence; the text fills `{count}`, `{s}` (a plural), `{biome}`, `{element}`, `{reaction}`, `{depth}` and `{rarity}` (`rarityNames`) from the data. Its progress lives on the entry; a claimed contract empties its slot (`contractsClaimed` + 1). `refillBoard` fills every empty slot and gives the visit's reroll back, on a new save and in `settleDive` after a dive that cleared a depth (never a start-and-abandon); `rerollContract` replaces one for `rerollScrap`, once a visit, refusing mid-dive, an empty slot, a completed contract ("Claim it first") and a spent reroll (pure: the Quests tab's dry run). **The view** is data: `questStates(registry, profile)` (the main quests in chain order, the side quests, then the board by slot; `status` active, complete or claimed, `isNew`, `tracked`, each reward a ref or `{ rule }`). Data: `src/data/quests.json` (`QuestsDataSchema`, `registry.getQuestsData()`: `giver`, `rarityNames`, `quests`, `contractTemplates`; `data/quests-check.ts` checks its references into the other files and that the main chain is one chain) and `balance.json → delve.quests` (`maxTracked`; `contracts`: `slots`, `tierWeights`, `depthScale`, `depthWindow`, `flagDepthBelow`, `rerollScrap`, `essenceChance`, `countScale`). The quests made the save version 9 (`profile.quests`: `progress`, `unlocked`, `claimed`, `tracked`, `seen`, `board`, `boardCount`, `contractsClaimed`, `rerollUsed`, `claimCount`); older saves reset. **The client:** `features/delve/quests/` (`useQuests` reads `questStates` through `quest-view.ts`, which names each reward with `materials-text.ts`, a rule by what it will be, "Chosen when you claim it", or "Claimed"); the **Quests tab** (`hub/quests/QuestsTab.tsx`): the journal (Main / Side / Contracts / a collapsed Done; NEW until opened, which marks it seen, and DONE while it waits), the open quest (Hesta, her line, the objectives with their bars) and its rewards with **Claim** (Enter, or A on the focused button; disabled while a dive is open, in the pause as at the Anvil mid-dive: "Claim after the dive"), **Track** (G / Y, up to `maxTracked`) and a contract's **Reroll** (R / X, priced, enabled by the engine's dry run, its refusal shown under it), an empty slot reading "New contract after your next dive"; the tab opens on the first quest that waits; under the pad A on the open, complete row claims it and the next one opens (with none left, the claimed quest stays open); **Claim all** (`quest-claim-all`) shows in the journal's head while two or more wait (between dives), claiming each in the journal's order through `claimQuest` and stopping at a refusal; the hub's Quests tab pip and the Depart sheet's "n to claim" (between dives) count what waits (`claimable`); the HUD's `QuestTracker` (in `FloorColumn`) shows up to `delve.quests.maxTracked` tracked quests. The store diffs `profile.quests` on every save (`questNotices` in `stores/delveStore.ts`, called in its `commit`): an objective newly done queues "Objective done: <text>", a quest whose last one is "Quest complete: <name> · claim at the Anvil" (instead of its objectives); `useDelveNotices` shows them. The dive banks pending quest events with the throttled pickups (`banksNow`, `BANK_EVERY`: a reaction not yet in `reactionsSeen` at once, a known one on the throttle), so the HUD tracker moves at each bank; a cleared floor completes on the save its last bank left (`clearFloor` in `arena/useArena.ts`), and the pause's Anvil flushes first, as Abandon does. **The autopilot** claims every completed quest and contract between dives, after binding and before anything else (`claimAll`), so the rewards feed its forging, and never rerolls; `economySim`'s rows carry `quests` (what the visit's claims gave), the Economy view's "from quests" line and column. - **Floor maps** (spec: `docs/superpowers/specs/2026-10-03-delve-floor-maps-design.md`; v0.60.0, save v10): a dive's floors are generated, 5–8 rooms joined by halls on a tile grid, found under a fog of war and left by an exit gate; the rooms past the way out are optional, for their packs and rewards. **The grid** (`src/types/floor-map.ts`, `arpg/grid.ts`): `ArpgWorld.map` is a `FloorMap` of 1-unit cells (`Cell`: 0 floor, 1 wall, 2 door, a wall while its door is closed; out of bounds a wall; 3–6 the room objects' cover, crumbling cover, foliage and slow ground, see Room objects) with its `rooms` (`Room`: `kind` start, combat, den, vault, sanctum (shown "Shrine"), alcove, exit or boss; `rect`, `arena`, `homeField`, `revealed`, `cleared`, `sealed`, `interactable`), `doors` (`Door.rooms[0]` the room whose wall holds it; `Door.held`, the guided start's gate, which no seal clears, and `doorShut(d)`, closed or held, the one test every reader makes: `isWall`, the fog key, the flow fields, the bot's door key), `start`, `exit` and `open`. `FloorOptions.layout` is `'open'` by default (`openRoom(width, height)`: the old arena exactly, one room, no leash, no fog, no gate, and `world.cleared` when every foe is dead), which the Training Grounds, the DPS Lab and `tests/fixtures/arena.ts` keep; only `beginFloor` passes `'generated'`, while `delve.layout.generatedDives` is on (as shipped; a test that needs it sets it on its own registry). Every mover goes through `moveCircle(map, pos, radius, dx, dy)` (axis by axis, swept so nothing tunnels; `shift` moves freely on the open room): the walk and separation, the dodge (a slice a tick), the pushes, foes and knockback, `pull`, the magnet and the vacuum, and every drop spawns on a walkable cell (`snapToWalkable`). Every hit site asks `sees(map, a, b)` (`lineOfSight`, a DDA raycast no diagonal crack sees through; always true on the open room): area hits, zones and Linger, reaction splash (`nearby()`), chains, Volley's homing, melee arcs and the foes' attacks; a shot stops at the wall's face, where a Bolt (and its Split) bursts; `clipSight` ends a beam, lands Blink and clips an aim point and Barrage's impacts; targeting (`nearestMonster`, `bestCluster`, `foeAhead`, `aimAt`) takes only foes in sight. **The generator** (`arpg/layout/generate.ts`: `generateFloor(registry, seed, depth, biome, door)`, and `planFloor` with each room's packs; pure, on the floor seed's `layout` fork, so the other streams' forks are untouched): rooms by a random walk on a `coarseCols` × `coarseRows` grid of `coarseCell` units (`rooms { base, perDepth, max }`), a spanning tree plus `loops` links, L-shaped halls `hallWidth` (3) wide, walls at least `minWall` thick; the start the walk's first room, the exit the farthest by graph distance (a boss floor's boss room, `layouts.json → boss`, the boss on the gate's point); the rest drawn from `kindWeights` by depth band (at most `alcoveMax` alcoves, vaults and sanctums toward dead ends by `deadEndWeight`, at least `minCombatRooms` combat rooms); the packs (the old count, `floorPacks`) spread up to `packsPerRoom` over the combat rooms and dens, at least `minPackDistance` from the start, combat rooms added when they don't fit; each foe's `roomId` (a boss's adds inherit it), each room's `homeField`, and an interactable at each special room's centre, its id `${depth}:${roomId}`. Room shapes come from `src/data/layouts.json` (`LayoutsDataSchema`: templates per biome, `default` for the rest, 12–20 cells a side, the boss room 20 × 20 and the arena's; and the props' sizes), furnished by set pieces (see Room objects); maps are at most 96 × 96 cells. **Foes** (`arpg/flow.ts`): a foe wakes on sight within `monster.aggroRadius` or when hit, its pack with it, and paths by a flow field toward the hero (`flowField`, a BFS rebuilt every `ai.flowEvery` within `ai.flowRadius`; three, `ArpgWorld.flow.small`, `large` and `huge`, by clearance class, `clearanceOf`: a foe wider than a cell needs a 3 × 3 square, one wider than three cells (a boss) a 5 × 5, its field built only while one stands; a field marks the cells whose square holds the target's cell a step from it, and the props' and hazards' footprints are blocked), stepping down it (`downhill`) or straight at the hero once it sees it within `ai.directRange`; a boss keeps to its room; separation runs on a spatial hash (`arpg/spatial.ts`). **The leash** (`leashTick`): an awake foe more than `terrain.leashMargin` outside its room's rect for `ai.leashSeconds` walks home down the room's `homeField` (`goingHome`, `homeWay`), heals and sleeps; hit on the way, it turns back. **Sealed rooms** (`arpg/seal.ts`, `sealTick`): a den or the boss room seals while the hero is inside with one of its foes awake (its foes outside brought in, each door shut once no one stands in it, and after `ai.sealGrace` whoever still does put out on their side; `seal`), and opens when none of its foes lives (`unseal`); a foe of it found in a blocked cell is put back on its floor, so a sealed room can always finish. **Room clears** (`onMonsterKilled` in `arpg/interact.ts`, called by `killMonster`): a room's last foe clears it (`roomCleared`) and, by `ai.roomVacuum`, pulls its foes' drops (`Drop.roomId`) to the hero; drops left when the exit is taken are lost. **Interacting** (`interactTick`): the `interact` action (`ArpgInput.interact`, a press like the potion's; C or pad A by default, left unbound and flagged in the Controls editor when a saved setup already uses its default) acts on the nearest unused interactable within `ai.interactRadius`, which sends `interactPrompt { id, interactable, text }` every step in reach: a vault's **chest** bursts `drops.vault` (flux, shards `shardTierUp` tiers up, an essence at `essenceChance`, never gear; `rollVault`; a vault may hold a guard pack, `vaultGuardChance`); a sanctum's **shrine** starts a prayer (`world.channel`, `ai.shrineChannel`) that a step, a dodge or a hit breaks and that blesses at its end (`applyShrine`, its shrine from `src/data/shrines.json` (`ShrinesDataSchema`), drawn at generation: damage, life or mana regen, Find, or a potion refill, for the floor (`HeroEntity.floorBuffs`) or the dive (`diveBuffs`); the hero's stats are `applyBuffs(baseStats, buffs)`, and `refreshWorldHero` puts the blessings back on); an **alcove** sends `alcoveOpen`, whose 2 or 3 stop kinds `alcoveOffers(registry, profile, world, id)` rolls on `alcove:<depth>:<roomId>` and whose one op `takeAlcove(registry, profile, world, action)` (`delve/stops.ts`) takes mid-floor with the lock lifted (it banks first and pays from `banked`, then the haul, then the stockpile); the **gate**, shut while a boss lives, sends `exitRequest { roomsUnexplored }`, answered with `exitFloor(world)`, which sets `world.exited`: a generated floor ends on it (`completeFloor`; `world.cleared` stays the open room's), and the foes left alive stay behind. Each one is used once a dive: `world.pending.used` and `diveBuffs` reach `DiveState.used` and `diveBuffs` in the same bank as the potions (`bankWorld`), so a replayed floor (the same map) finds them used and the next floors wear the dive's blessings (`FloorOptions.used`, `diveBuffs`). An elite den's elites add `drops.den.gearBonus` to their gear chance (`DropContext.gearBonus`). **Rooms cleared:** on a generated floor `completeFloor`'s `clearFloor` event carries `roomsCleared` (the rooms whose foes all died; a room that spawned none never counts), and a `clearFloor` objective's or contract template's `minRoomsCleared` must be met (Untouchable and Dry Run ask 2), so sneaking to the exit doesn't complete them. **Fog** (`arpg/fog.ts`): `ArpgWorld.fog` (0 unseen, 1 seen, 2 in sight), lit at `ai.fogEvery` marks (`fogTick`, recomputing sight only when the hero's cell or a door changes) within `ai.sightRadius` by line of sight, entering a room revealing it whole; `fogVersion` moves with it; after `ai.exitHintSeconds` with the exit's room unrevealed `exitHint` fires once (`exitHinted`); `hudMapOf(world)` (pure) is the minimap's: the revealed rooms and their icons, the exit and its hint, foes in sight, drops in seen cells, and rooms explored. The open room is all in sight, and every hook above is a no-op on it. Numbers: `balance.json → delve.layout`, `delve.ai`, `delve.drops.vault` and `den`. The floor maps made the save version 10 (`DiveState.used`, `diveBuffs`); older saves reset. **The bot** (`arpg/bot.ts`, `botInput(registry, world, policy)`; `botStep` in `delve/autopilot.ts`): on a generated floor it walks by its own flow fields over a copy of the map with the standing room objects and its one-cell gaps walled (`heroMap`), fights the foes it sees and plays a `BotPolicy` (`AutopilotOptions.policy`): `thorough`, the default (what it has seen on the floor, the foes of rooms it has entered, the unused chests, shrines and alcoves, the rooms not yet entered, then the gate; with no potions left it plays as a beeline), or `beeline` (the nearest room not yet entered until the exit's is found or hinted, then the gate, fighting what blocks it and never following a foe into a den); it answers `exitRequest` with `exitFloor` and `alcoveOpen` with `takeBestAlcove(registry, profile, world, id)` (the stop's ladder over the alcove's offers); `playFloor` ends on `world.exited`, and a floor past `maxFloorSeconds` (420) counts as a death and in the report's `timedOut`; `pickDoor` extracts for a banked essence only when the stockpile holds the epic flux to forge it, and at a boss depth until the save's first extract. Measured at v0.60.0 over 8 Fire seeds: dive 12's mean depth 41.5 thorough and 42.6 beeline (dive 9's 33.0 and 29.9), a floor about 39 s thorough and 28 s beeline, the bot dying in about 60–67% of its dives. **The client:** the pixel floor is built from the map (see Pixel floor); the renderer draws the doors (`drawDoor`: bars slide shut, glowing red while sealed), the props by state (`propFrame`: a chest open, a shrine spent, the gate open once no boss lives; the `chest`, `shrine`, `alcove_anvil` and `exit_gate` code sprites from `packages/pixel-forge`) and the fog (`paintFog`: unseen black, seen dimmed), hides foes, their marks and wind-ups out of sight, and shows loot plaques only where the fog has seen (`seenAt`); the camera clamps to the map; the snapshot's `HudMap.floor` is `hudMapOf`'s with the world's own `cells` and `fog`, and the `Minimap` draws its fog layer (redrawn only when `fogVersion` moves), the revealed rooms' outlines (a sealed one's red) and icons, and a compass toward a hinted exit; `FloorColumn` shows "Rooms explored n / m" (`rooms-explored`) on a generated floor and "foes left" only on the open room; `InteractPlaque` (DOM over the prop, in the HUD's zoom) shows the interact input for the device holding the input lock and its verb (chest Open, shrine Pray, then Praying with the prayer's bar, alcove Forge, gate Leave) over the engine's text; the gate's `ExitConfirm` ("Leave the floor?", the rooms unexplored, "Loot left on the floor is lost.", Back focused, so a second A never leaves) and the `AlcoveDialog` (the stop's cards, `StopPanel` with `ops`: `takeStop` dry runs, the take through `takeAlcove`; with nothing affordable, a notice instead) pause the fight (`arena/FloorDialogs.tsx`; `routeFloorEvents` in `arena/useArena.ts`, where the autopilot takes the exit and its alcove pick at once); the shrines' blessings join the buff row (the `shrine` glyph, cyan for the floor, gold for the dive); - **Mana-pixel FX** (`features/delve/arena/fx/`): every combat effect (shields, zones, telegraphs, projectiles, swings, casts, aim markers, monster marks) is drawn as mana pixels on the sprites' 0.1-unit grid rather than as smooth shapes. `mana-pixels.ts` is the vocabulary (`manaRing`, `manaDust`, `manaMotes`, `manaArc`, `manaLine`, `manaOrb`), `pixel-layer.ts` rasterises a Graphics into a grid-snapped texture (a ground layer and an additive air layer), `draw-world.ts` draws the world's persistent effects each frame (a hazard's glow and telegraph too, `drawHazards`), `room-objects.ts` the room objects' moments (see Room objects), and `mana-fx.ts` holds the short-lived ones plus the casting polish (a fling of mana on every cast and basic, and melee smears that sweep across their arc). The page (`pages/DelveLab.tsx`, `features/delve/lab/`) is a kit `Screen` on the wall: a band header with the view `Tabs` (`lab-tab-<view>`, LB/RB) and "◂ Training" (`lab-back`, Esc or B), the run controls (its native range, checkbox and selects) and the filter `Chip`s in a well, and the chart and the ranked table in a plate. It runs the grid in a fresh worker per request, under a Mana select beside Pack (full, starved, supported; `lab-mana`), and keeps results for the session by depth, pack and mana (`remember` / `recall`); `lab/dev-routes.tsx` makes the lazy route (`DEV_LAB`) at module scope, so production builds drop it. Its **Economy** view (`lab/EconomyView.tsx`, `economy-model.ts`, `economy-worker.ts`) runs `economySim` for chosen seeds and dives in a worker and charts, dive by dive, the mean over the seeds of a material's income, its quest rewards, the Anvil's salvage, the spending (the Anvil's and the stops') and death loss, the items forged by rarity, the deepest depth or the deaths, over a table of every dive.
- **Test hooks**: localStorage `alloy:delve:autopilot = "1"` lets the engine bot play the arena, a guided floor's steps too (E2E uses it, `e2e/delve-tutorial.spec.ts` answering the beats, the stops and the lesson as a player; `"ask"`: the bot plays, but waits at each interactable for the player's interact press, and the gate's and an alcove's dialogs open as for a player: `readArenaFlags().ask`); `alloy:delve:timescale` speeds up the sim (max 4×).
