## Goal

Every skill (Basic, Primary, Defensive, Ultimate) becomes a **chain of moves**. A move has a kind (light, medium, heavy, or hold), a form from the skill's list, and one or two elements from the hero's pair; a basic blow has a kind and an element. Each press casts the chain's next move; a hold move charges while the button is held and fires on release. The player builds combos across skills and across moves, on top of stage 2's stacks: two quick fire blows, a medium frost Bolt, a double Melt.

## Decisions

| Question | Decision |
|---|---|
| How a chain plays | Each press casts the next move within the combo window; a pause restarts at move 1; a held button repeats presses (hold-to-repeat), so it flows through the chain at the moves' cadence. Basics auto-chain as today. |
| Hold | A fourth kind: holding the button charges (rooted, mana gathering), releasing fires. Three charge stages over `holdTime` mapping to weights 0, +1, +2, so a tap is a medium hit and a full hold is beyond heavy. |
| What a slot holds | Kind, form (from that skill's list) and elements (from the pair), per move. Payment stays one per skill. Acquired modifiers are stage 4. |
| Cooldowns | Per move: each move cools on its own and a press waits only for the *next* move's cooldown. Ward → Blink is a real E, E; a four-Bolt Primary can burst all four, then mana and the moves' own cooldowns pace it. |
| Carrying a combo forward | Each move after the first lands harder: `stepBonus` (+10% power per position, half of it on size) replaces the per-press multipliers the forms had, so a long chain pays off without per-form tables. |
| Basics | Per blow: kind and element (either of the pair). The weapon owns melee-or-bolt, tempo, arc, range and a feel table per kind derived so that its default chain reproduces today's string blow for blow. A blow keeps today's stack counts by kind. |
| Caps | Up to 5 moves per skill (`MAX_CHAIN`), the cap held per skill on the profile at the balance default (5 for all this stage). Stage 4 sets starting caps and growth by investment (crafting, experience, or both). |
| Defaults and migration | Save v5. New heroes and migrated builds alike get each form's default chain (Bolt: light, light, medium, heavy), so the escalation press-combos give today is kept. |

## The model

### Types

```ts
type MoveKind = 'light' | 'medium' | 'heavy' | 'hold';            // MOVE_KINDS in that order
interface Move { kind: MoveKind; form: FormId; elements: ManaType[] }  // 1–2 distinct elements
interface Chain { moves: Move[]; payment: AbilityPayment }         // 1..cap moves
interface Blow { kind: MoveKind; element: ManaType }
type ChainSkill = 'basic' | AbilitySlot;                           // CHAIN_SKILLS: basic, primary, defensive, ultimate
interface Chains { basic: Blow[]; primary: Chain; defensive: Chain; ultimate: Chain }
const MAX_CHAIN = 5;
DelveProfile.chains: Chains; DelveProfile.chainCaps: Record<ChainSkill, number>;   // 1..MAX_CHAIN
```

`AbilitySlot` stays the three ability slots (indexes 0, 1, 2 keep their meanings everywhere); the basic chain feeds the weapon, not a slot. `AbilityBuild`/`AbilityBuilds` survive only in the frozen v3/v4 save schemas and the migration.

**Kind → weight.** `chains.kindWeight` = light −1, medium 0, heavy +1; a hold's three stages use `chains.holdStageWeight` = [0, 1, 2]. Every per-weight table (power, cost, cooldown, conjure, recovery, heft, size, speed, `stacks.byWeight`) is read through them, so nothing is retuned. Swift (−2) and Crushing (+2) are no longer fixed picks.

### Resolving a chain

`resolveChain(registry, stats, slot, chain) → ResolvedChain { moves: ResolvedAbility[]; payment; hold: (ResolvedAbility[] | null)[] }`: each move resolves through today's `resolveAbility` at its kind's weight with the chain's payment; a hold move also resolves its three stages into `hold[i]` (weights 0, +1, +2), and `moves[i]` is its stage 0. The forms' `combo` multipliers and `comboCount` leave the data: a chain's escalation is its kinds plus the **step bonus**: move `i` (0-based) lands at power × `(1 + stepBonus × i)` and size × `(1 + stepBonus × i / 2)`, applied where the old `combo[step]` multiplier was: the power factor on `executeForm`'s hit, the size factor on Bolt's projectile and explode radius, Lance's length, Burst's radius and the recoil and step-in motion. A chain carries its combo forward as the press-combos did, and `estimateCombat`'s damage per use averages the power factor over the chain. Volley's dart count becomes `countByKind: Record<MoveKind, number>` on the form (3, 3, 5, 5; a hold's stage 2 uses `hold`). `stepHeft`'s +0.2 and Strike's slam key on the last move of a 2+ chain.

The hero holds `chains: ResolvedChain[]` (index = slot); `h.abilities` goes. `nextMove(h, slot, t)` is the move the next press would cast (within the window: the step after the last landed; otherwise move 1; the chain wraps after its last move). `activeMove(h, slot)` is the move winding up (`windup.step`), holding (`hold.step`), or, for the Defensive, up (`h.defend.move`, an index set by `buff()`). Every reader of `h.abilities[slot]` today reads one of those: the bot (`nextMove`'s range), `defendingAbility`/`surging`/`shieldHero`/`wardBurst`/`defendTick` (`chains[1].moves[h.defend.move]`), Nightstalker (the Defensive chain's next move), Galvanize, the HUD snapshot, `refreshWorldHero`, the DPS sim, the anticipation and Ward FX (`abilities[1]` in `draw-world.ts`, `lifecycles.ts`, `ArenaRenderer.ts`), the pad aim view (`abilities[0]`). `FloorOptions.abilities`, `SandboxWorldOptions.abilities`, `ArenaMode.loadout.abilities` and `DpsSetup.abilities` become `chains: Chains`; `sameBuild` becomes `sameChain`.

### Chain play

- **Stepping.** `pressStep` keeps its rule against the chain's length: within `comboWindow` (1.2 s) of the last move landing, the next move; otherwise move 1. `comboStep`/`comboAt` per slot as today; the wind-up carries `step` as today. A chain edit that shortens the chain clamps `comboStep`.
- **Cooldowns are per move.** `h.cooldowns[slot][move]`; a landed move sets its own; `abilityReady(slot)` checks the next move's; Galvanize takes its seconds off every move of the slot; Nightstalker reads the Defensive's next move; the HUD shows the next move's. The Training Grounds' No cooldowns clears them all.
- **Payment.** One per chain. Each move pays its own resolved cost through it: mana at the press; charge from the slot's meter, where `chargeNeed` is per move (a hold's is its stage 2's), the meter caps at the chain's largest need (`gainCharge` and the sandbox fill), a press compares the meter with the next move's need, only `refreshWorldHero` clamps it, and `gainCharge` (own hits and the lull) skips a slot while *any* of its moves' cooldowns runs, which for a charge chain is the lockout of whichever move last fired, as today; cast with its channel and discount. A move that can't be afforded is refused as today (`noMana`) and the chain doesn't advance.
- **Defensive chains.** The next press replaces the active defensive with the next move's effect: `buff()` clears the old effect (Ward hp, Surge, the Blink trail) as a changed Defensive is cleared today, and sets `h.defend = { form, until, move }`.

### Hold

- **Input.** `ArpgInput` gains `holding?: number | null`: the ability slot whose button is held this tick, and `cancelHold?: boolean`: drop a running hold unpaid (the HUD button's release-back gesture sends it). `cast` stays the press edge for every move and is the *release* edge for a hold move.
- **Starting.** When `holding` names a slot whose `nextMove` is a hold and the hero is free as `castAbility` requires (no wind-up, no hold, not dashing; a swing in its startup is cancelled, push and recovery cleared, exactly as a cast does), and stage 0 is affordable, `h.hold = { slot, step, start, aim }` begins. `h.hold` gates input and ages nothing exactly as `h.windup` does everywhere `h.windup` is checked (`startSwing`, `abilityReady`, `castAbility`, the queued-cast buffer, movement, the dodge). A `cast` for another slot during a hold is buffered unaged and fires after the release.
- **Charging.** While `holding` stays on the slot the hero is rooted, the anticipation FX gather mana with the charge, and the combo window is paused (the `comboAt` clock stops). `charge = min(1, (t − start) / holdTime)`; the stage is 0, 1 or 2 by `holdStages` ([0.33, 0.66]); a `holdStage` event fires when the stage rises.
- **Release.** A `cast` for that slot while its hold runs fires `hold[stage]` at the release aim, paying that stage's cost and setting its cooldown and stacks. The time spent charging counts toward that stage's wind-up (its conjure, and its channel for cast payment): what is left of `castTime − (t − start)` runs as an ordinary wind-up (no step-in), so a quick tap pays the full medium wind-up and a long hold fires at once. A hold can never beat a plain medium move by skipping its wind-up. Past `holdMax` (2 s) it fires by itself at stage 2. If `holding` stops without a `cast` (a lost release) it fires at the current stage. A stage that can't be afforded on release falls to the highest affordable stage; if none, the hold cancels unpaid. A dodge, `cancelHold`, and `refreshWorldHero` on a changed slot all cancel it unpaid. A dropped or auto-fired hold marks its slot (`world.holdDropped`); while that slot's button stays held, its release `cast` is swallowed and no new hold starts, so dodging out of a charge (or holding past `holdMax`) never fires a stray tap or the chain's next move on release.
- **Tap.** A `cast` for a slot whose next move is a hold with no hold running fires stage 0 with its full wind-up: a tap is a medium hit.
- **Hold-to-repeat.** A held button doesn't re-press while the next move is a hold: the pad frame sends `holding` instead. So "quick, quick, hold, heavy" under a held button plays quick, quick, then charges until the button lifts, then heavy on the next press.
- **HUD busy.** A hold dims the other buttons as a channel does.

### Basics

- **Data.** `GearBaseDef.combo` becomes `GearBaseDef.feel: Record<MoveKind, ComboStepDef>` and `GearBaseDef.defaultChain: MoveKind[]`; the unarmed string (`balance.json → delve.hero.defaultCombo`) becomes `hero.feel` and `hero.defaultChain` likewise. The rows are derived so that **each weapon's default chain reproduces today's string blow for blow**:
  - strings of 3+ blows: light = blow 1, heavy = the finisher, medium = the last ordinary blow when it differs from blow 1 (the dagger's third blow), else halfway between light and heavy in every number;
  - the maul's 2-blow string: medium = blow 1, heavy = blow 2, light = medium at power × 0.8, time × 0.85, startup × 0.9, heft × 0.75, move × 0.8;
  - hold = heavy with startup × 1.5, power × 1.3, heft + 0.2 (capped at 1).
  - Default chains: dagger light, light, medium, heavy; sword, axe, staff, wand, bow light, light, heavy; maul medium, heavy; unarmed as its string maps.
- **Stats.** `HeroWeapon` keeps the weapon's `feel` table and carries `blows: (ComboStepDef & { kind; element; power })[]` built from the basic chain and that table (a hold blow's row is the hold row; its stages read `feel.medium`/`feel.heavy`/`feel.hold` at strike time), where `power` = `1 + basicPowerPerAttune × att[element]` (today's `blowPower`/`finisherPower`, per blow); `element`, `infusion`, `blowPower`, `finisherPower` and `combo` go. `computeHeroStats` takes the chain through `HeroStatsExtra.basic?: Blow[]`; `profileStats`/`pairExtra` pass `profile.chains.basic`; the Training Grounds pass the sandbox's; with none it uses the weapon's default chain on the pair (last blow the secondary when bound, else the primary). A blow's element is always a `ManaType`: with no primary chosen yet, the weapon's mana, else fire, as `defaultAbilities` falls back today.
- **Strikes.** `strike` reads the blow's element, power and kind: its status is `BASIC_STATUS[element]`, its stacks `stacks.basicByKind[kind]` = light 1, medium 1, heavy 2, hold 2 (today's blow 1 / finisher 2, so basics don't change; `basicBlow`/`basicFinisher` go), Twin Fang still doubles the last blow. The finisher discharge rule goes: every blow applies its own element's stack, as stage 2 made it. The `basic` event keeps `step` and gains `kind` and `element`; `finisher` goes.
- **Hold blows.** In manual attack mode a hold blow's swing starts with the medium row's startup and lunge; at its strike point, while `attack` is still held, it holds there charging (stages by `holdStages`, capped at `holdMax`), and strikes on release with the stage's row (stage 0 medium, 1 heavy, 2 hold: power, heft, arc, reach, knockback, size, explode, speed), setting `cycle` from that row, `nextAttackAt = release + cycle × (1 − startup)` (the startup was spent holding) and the recovery from that row. In automatic mode it plays the hold row straight, with no charging: a slow, hard blow in the string. An ability press while a manual hold blow charges cancels the blow unstruck, as an ability press cancels a swing in its startup today; a manual attack held continuously charges each hold blow to `holdMax`. A basic-chain edit that changes the blows (kinds or count) drops an in-flight swing in `refreshWorldHero`, as a weapon swap does.
- **Power.** `estimateCombat` values the chain: each blow's power × its element's power, summed over the string's time, as today's formula with per-blow terms; `compareItem`/`heroPower` without chains use the weapon's default chain.
- **Visuals.** A blow draws in its own element's colour; the finisher ring draws for heavy and hold blows in the blow's element; the basic-attack infusion motif (`basicMotif`, `shotInfusion`, `burstShot`'s infusion) goes, since a blow has one element. Ability infusions are unchanged.

### Save v5

- `DelveProfile.version` 5, `chains`, `chainCaps`; `abilities` goes. `DelveProfileSchema` v5 with `MoveSchema`, `BlowSchema`, `ChainSchema` (1–`MAX_CHAIN` moves; forms of the right slot; 1–2 distinct elements) and `chainCaps` (1–`MAX_CHAIN` each). The frozen v4 schema is kept as `DelveProfileV4Schema` (today's), v3 and v2 as they are; `parseDelveProfile` chains v2 → v3 → v4 → v5.
- **Migration v4 → v5.** Per ability slot: kinds from the form's `defaultChain` (in `arpg.json`, replacing `combo`; derived from the old multipliers with ≤ 0.9 light, ≤ 1.2 medium, else heavy: Bolt L L M H, Volley M M M, Lance M M H, Burst M M H, Strike M M M H; Defensive and Ultimate forms a single medium), each shifted one step lighter for weight −2/−1 and one heavier for +1/+2 (clamped to light..heavy; hold never appears from migration), elements and payment from the build. Basics: the weapon's `defaultChain` with the last blow the secondary when bound, else the primary (the fallback above when no primary). Caps: the balance default. `fixed` notices become per-move (`ChainFix { skill, index, removed, move }`: "Your Bolt's 3rd move used Frost, which isn't in your pair; it now uses Fire").
- **Ops** (`profile.ts`/`pair.ts`): `setChain(registry, profile, skill, chain)` replaces `setAbility` (refuses mid-dive, more than the cap or fewer than 1 move, a form from another slot, an off-pair or duplicate element, an unknown kind); `defaultChains(registry, element, weaponBaseId)` replaces `defaultAbilities`: each form's `defaultChain` on the element (Bolt L L M H, Ward M, Nova M) with today's payments, and the weapon's default basic chain; `fixChainsToPair` replaces `fixBuildsToPair`: when a pair op replaces an element (a realign, an overtake, a bind), each move's and each blow's element that left the pair becomes the element that took its role (the new primary or the new secondary), so Storm blows become Nature when the secondary goes from Storm to Nature, and a Fire+Storm move stays fused as Fire+Nature; with no replacement (the migration from v4) it keeps in-pair elements and an emptied move or blow takes the primary, as today; `chooseStartingMana`, `bindSecondary`, `realign` and `reattune` keep their contracts on the new shapes (`ProfileActionResult.fixed`/`ParsedDelveProfile.fixed` are `ChainFix[]`). The chain caps are written by nothing yet (stage 4 adds the growth).

### Balance and data

`balance.json → delve.chains`: `cap` {basic 5, primary 5, defensive 5, ultimate 5}, `kindWeight` {light −1, medium 0, heavy 1}, `holdStageWeight` [0, 1, 2], `holdTime` 1.0, `holdMax` 2.0, `holdStages` [0.33, 0.66], `stepBonus` 0.1 to start. The plan's gate settled `stepBonus` 0.15 and two default chains: Bolt light, medium, medium, heavy (two lights put too few frost stacks on for Shatter) and Strike medium, medium, heavy, heavy (a heavier third move spaces the presses past the reaction lockout); the chains above read with those. `delve.stacks.basicByKind` {light 1, medium 1, heavy 2, hold 2} replaces `basicBlow`/`basicFinisher`. `arpg.json` forms lose `combo`/`comboCount` and gain `defaultChain` (and Volley `countByKind`). `delve.json` bases lose `combo` and gain `feel` and `defaultChain`; `hero.defaultCombo` becomes `hero.feel` + `hero.defaultChain`. `comboWindow` stays in `delve.abilities`.

### Bot and autopilot

- The bot presses as today, so chains flow; its cast decision reads `nextMove`. When the next move is a hold it sets `holding` until `charge` reaches 1, then sends `cast`; it never taps a hold.
- `bindBest` sets every move of the Primary chain to `[primary, secondary]`; the sweep and the reactions rail keep their meaning. Defaults come from `defaultChains`, so the bot's Primary keeps the escalation it cycles today.

### DPS Lab

`dpsCombos` enumerates: single-move chains, non-Defensive forms × 36 ordered element sets × 4 kinds × 3 payments (3,456), dims `{ form, first, second, kind, payment }`, each on `defaultChains(first, 'sword')` with that slot's chain replaced; and each form's default chain (`kind: 'default'`) × 36 × 3 payments (864), which is what a held button plays and what the gate compares. A hold move is held to full charge each press (the sim sends `holding` for `holdTime`, then `cast`). Basics: each weapon's default chain × the pair (252, as today). `simulateDps` needs no other change.

## What you see

- **The chain builder** (`AbilitiesPanel` → `ChainEditor`). The Abilities tab lists the four skills, Basic first, as `role="tab"` buttons (the D-pad and A reach them; the Anvil's LB/RB tab bar is unchanged). A skill shows a row of slot cards, one per move, up to its cap: each card shows the kind (an icon: ▪ light, ▪▪ medium, ▪▪▪ heavy, ◉ hold), the form's icon and name (basics: the weapon's blow), and its element chip(s). Tapping a card opens the move editor below the row: kind chips, the skill's form chips (none for basics), main element and infusion chips from the pair (basics: one element), and the readout (cost, wind-up, cooldown, stacks). Between the cards: ◂ ▸ to reorder, × to remove (not the last), and a + card while under the cap. Payment chips sit once per ability chain. The summary line names each move with its element or fusion: "light Fire Bolt · light Fire Bolt · medium Fire Bolt · heavy Fire Bolt", "medium Wildfire Burst" (`chain-text.ts`, shared with the HUD's aria-labels, which name the next move: "Primary: light Fire Bolt"). The Training Grounds' editor is the same component on the sandbox store (`chains`, `ChainSchema` with today's slot refine, `.catch(defaults)`; `loadMyBuild` copies the chains and the pair), unrestricted as today; its "Basic infusion" row becomes "Your secondary": the second element the sandbox's basic blows can pick.
- **HUD.** Each ability button shows its chain as step dots (the next move's dot lit; `chainStep`/`chainLength` replace `comboNext`/`comboLength`), a kind glyph for the next move, and while holding a charge fill that ticks through the three stages. The manual attack button shows the basic chain the same way. `AbilityHud` gains `nextKind` and `hold: { charge, stage } | null`.
- **Input.** Keyboard: keydown sends `holding` (and starts aiming as today), keyup sends `cast`. HUD buttons: pointer-down `holding`, pointer-up `cast`, the release-back gesture cancels. Controller: a held RT/LB/R3 sends `holding`; the pad frame decides per slot from `nextMove(world.hero, slot, world.t)` (not the HUD snapshot): for a hold next-move the *release* edge sends `cast` and hold-to-repeat is suppressed; otherwise the press edge sends `cast` as today.
- **Arena.** The anticipation FX read the active move and grow with the charge during a hold; the `holdStage` event pings a ring; the cast fling and the basic swing FX read the blow's kind and element. Reaction and stack visuals are unchanged.
- **Texts.** DelveCamp's how-to describes chains; the ability-system spec's press-combo texts in `arpg.json` describe default chains.
