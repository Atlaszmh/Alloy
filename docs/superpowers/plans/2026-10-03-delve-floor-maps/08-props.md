# Delve floor maps C3 · Props Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The four floor-map props get code-drawn sprites in the Delve atlas: `chest` (closed, open), `shrine` (lit, spent), `alcove_anvil` (idle flicker, 2 frames) and `exit_gate` (closed, open), each at 16 px per unit of its prop size.

**Architecture:** One `CodeSprite` per prop in `packages/pixel-forge/art/alloy/sprites/` (the legend-and-rows format of `hesta.ts`, ENDESGA 32 colours, a `#181425` outline, art bottom-centred on a square canvas), one `code` entry each in `art/alloy/manifest.json` (its px `size` plus its prop size in units, `units`, a new optional `AssetSpec` field), and `forge build` rewrites the atlas and `review.png`. The client's atlas test learns the ids and a props size rule. No runtime code: C1 draws them from the atlas.

**Prop sizes (units → canvas px):** `chest` 0.9 → 14, `shrine` 1.4 → 22, `alcove_anvil` 1.4 → 22, `exit_gate` 2.6 → 42. Phase A puts the same values in `layouts.json → props` (which doesn't exist on `maps/main` yet); until then the atlas test holds them.

**Tech Stack:** `packages/pixel-forge` (tsx CLI), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-03-delve-floor-maps-design.md` ("Rendering → Props", the C3 row). **Branch:** `maps/c3` from `maps/main` (worktree `C:/Projects/alloy-maps-c3`).
